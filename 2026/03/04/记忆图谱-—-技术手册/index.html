1. 项目概述

1.1 项目目标

本项目是一个 “历史背景注入” 模块，核心能力是：

  1. 从用户输入的回忆录文本中自动提取时间、地点、关键事件
  2. 基于 Microsoft GraphRAG 构建的知识图谱检索相关历史背景信息
  3. 使用大语言模型 (LLM) 将历史事实润色为具有文学性的描述
  4. 将生成的内容无缝融入个人叙事中

1.2 核心技术

技术 用途 说明
Microsoft GraphRAG 知识图谱索引与检索 从文档中抽取实体/关系，构建分层社区摘要
LiteLLM 统一 LLM 调用接口 一套代码支持多个 LLM 提供商
Ollama 本地大模型部署 运行 Qwen3:32b，无需云端 API
Gradio Web 交互界面 提供可视化操作界面
FastAPI REST API 后端 提供程序化调用接口
Pydantic-Settings 配置管理 从 .env 自动加载环境变量

3. 环境部署

3.1 前置条件

依赖项 版本要求 说明
Python 3.10 - 3.12 GraphRAG 的 Python 版本要求

Ollama - 本地大模型推理框架
Qwen3:32b - 通过 Ollama 部署的本地模型

3.2 安装步骤

Step 1：创建 conda 环境

conda create -n RAG python=3.10 -y
conda activate RAG

Step 2：安装 Python 依赖

cd /data/jiabao/RAG/GraphRAG

主要依赖：

pydantic-settings ≥2.3.0 配置管理

Step 3：配置环境变量

cp env.example .env

4.2 多 LLM 适配层 (llm)

4.2.1 适配器架构

文件：src/llm/adapter.py

采用 策略模式 设计，所有 LLM 提供商通过统一接口调用：

LLMAdapter (抽象基类)
├── DeepseekAdapter    → deepseek/deepseek-chat
├── QwenAdapter        → openai/qwen-plus (兼容接口)
├── HunyuanAdapter     → hunyuan/hunyuan-lite
├── GeminiAdapter      → gemini/gemini-2.0-flash
├── OpenAIAdapter      → gpt-4o-mini
└── OllamaAdapter      → ollama_chat/qwen3:32b (本地)  ← 新增

核心接口：

方法 说明 参数
chat() 异步聊天接口 messages, temperature, max_tokens
chat_sync() 同步聊天接口 同上
generate() 简化生成接口 prompt, system_prompt, temperature

LLMResponse 数据结构：

字段 类型 说明
content str 生成的文本内容
model str 使用的模型名称
provider LLMProvider 提供商枚举
usage Dict[str, int] Token 使用量
finish_reason str 结束原因

4.2.2 适配器工厂

文件：src/llm/factory.py

函数 说明
create_llm_adapter(provider, model, api_key, api_base) 创建指定提供商的适配器实例
get_available_providers() 返回所有提供商及其可用状态
get_all_adapters() 返回所有已配置的适配器实例

使用示例：

from src.llm import create_llm_adapter

# 使用默认配置（Ollama 本地模型）
adapter = create_llm_adapter()

# 指定提供商
adapter = create_llm_adapter(provider="ollama", model="qwen3:32b")

# 调用
response = await adapter.generate(
    prompt="1988年深圳有什么历史事件？",
    system_prompt="你是一位历史学者",
    temperature=0.7,
)
print(response.content)

4.2.3 多 LLM 路由器

文件：src/llm/router.py

支持三种调用模式：

模式 方法 说明
单模型调用 generate() 使用指定或默认的单个 LLM
并行对比 generate_parallel() 同时调用多个 LLM，收集所有结果
故障转移 generate_with_fallback() 按优先级依次尝试，直到成功

使用示例：

from src.llm import LLMRouter

router = LLMRouter()  # 自动加载所有可用适配器

# 并行调用多个模型
results = await router.generate_parallel(
    prompt="描述1988年的深圳",
    providers=["ollama", "deepseek"],
    temperature=0.7,
)

for provider, response in results.responses.items():
    print(f"[{provider}] {response.content[:100]}...")

4.3.2 GraphRAG 索引构建器

文件：src/indexing/graph_builder.py

GraphBuilder 类封装了 Microsoft GraphRAG 的完整索引流程：

构建流程：

输入 TXT 文件 → GraphRAG Init → 生成 settings.yaml → 创建 .env
     → 运行 graphrag index → 输出 Parquet + LanceDB 索引

索引产出：

输出文件 内容 说明
entities.parquet 抽取的实体 人物、地点、事件、组织等
relationships.parquet 实体间关系 因果、时间、空间关系
communities.parquet 社区聚类 Leiden 算法检测的实体社区
community_reports.parquet 社区报告 LLM 生成的社区摘要
text_units.parquet 文本块 原始文本的分块
lancedb/ 向量索引 嵌入向量数据库

自定义实体类型（针对历史事件场景）：

ENTITY_TYPES = [
    "历史事件", "人物", "地点", "时间",
    "组织", "政策", "社会现象", "经济指标", "文化运动",
]

支持的 LLM 配置（用于索引构建）：

提供商 model_provider 说明
ollama openai (兼容接口) 本地模型，并发数=1，避免 OOM
deepseek deepseek 云端 API
qwen openai (兼容接口) 阿里云
gemini gemini Google AI
openai openai OpenAI 原生

使用示例：

from src.indexing import GraphBuilder

# 使用 Ollama 本地模型构建索引
builder = GraphBuilder(llm_provider="ollama")

# 同步构建
result = builder.build_index_sync()
print(result.message)  # "知识图谱索引构建成功"

# 查看索引统计
stats = builder.get_index_stats()
print(f"实体: {stats['entities']}  关系: {stats['relationships']}")

4.4 检索模块 (retrieval)

4.4.1 回忆录解析器

文件：src/retrieval/memoir_parser.py

MemoirParser 从回忆录文本中提取结构化信息，支持两种模式：

模式 方法 说明
规则提取 parse() 正则表达式匹配年份、月份、地点、关键词
LLM 深度解析 parse_with_llm() 先规则提取，再用 LLM 补充和修正

规则提取能力：

提取项 示例 正则模式
年份 1988年 / 88年 / 一九八八年 多种中文数字格式
月份 8月 / 八月 阿拉伯+中文数字
地点 来到深圳 / 广东省 动词+地名 / 行政区划
关键词 改革开放 / 经济特区 预定义历史事件词库

MemoirContext 数据结构：

字段 类型 说明
original_text str 原始回忆录文本
year str 提取的年份
month str 提取的月份
location str 提取的地点
keywords List[str] 提取的关键词
entities List[Dict] LLM 提取的实体列表

4.4.2 知识图谱检索器

文件：src/retrieval/memoir_retriever.py

MemoirRetriever 在 GraphRAG 索引中搜索相关历史信息：

检索流程：

回忆录文本 → MemoirParser → MemoirContext → 构建查询
     → 实体匹配 (关键词匹配 Parquet)
     → 关系匹配
     → 社区报告匹配
     → 文本单元匹配
     → 汇总为 RetrievalResult

检索策略（当前实现）：

检索类型 数据源 匹配方式
实体检索 entities.parquet 关键词字符串匹配 + 评分排序
关系检索 relationships.parquet 源/目标实体名匹配
社区检索 community_reports.parquet 标题/摘要/内容关键词匹配
文本检索 text_units.parquet 关键词在原文中出现频次

RetrievalResult 数据结构：

字段 类型 说明
query str 生成的检索查询
context MemoirContext 解析的上下文信息
entities List[Dict] 匹配的实体列表
relationships List[Dict] 匹配的关系列表
communities List[Dict] 匹配的社区报告
text_units List[str] 匹配的文本段落

使用示例：

from src.llm import create_llm_adapter
from src.retrieval import MemoirRetriever

adapter = create_llm_adapter(provider="ollama")
retriever = MemoirRetriever(llm_adapter=adapter)

result = await retriever.retrieve(
    memoir_text="1988年夏天，我从大学毕业来到深圳...",
    top_k=10,
    use_llm_parsing=True,
)

print(f"找到 {len(result.entities)} 个相关实体")
print(f"找到 {len(result.communities)} 个社区报告")
print(result.get_context_text())  # 获取格式化的上下文

4.5 文学生成模块 (generation)

4.5.1 文学润色生成器

文件：src/generation/literary_generator.py

LiteraryGenerator 将检索到的历史背景信息转化为具有文学性的描述：

核心功能：

方法 说明
generate() 单模型生成历史背景描述
generate_parallel() 多模型并行生成（用于对比）
enhance_memoir() 将生成内容插入回忆录（before/after/interspersed）

生成流程：

回忆录原文 + RetrievalResult
    → 构建 Prompt (年份/地点/检索到的历史信息)
    → LLM 生成 (使用系统提示词约束风格)
    → 返回 GenerationResult

系统提示词约束 LLM 的行为：

  • 使用温暖、怀旧的笔调
  • 将历史事件与个人经历自然衔接
  • 使用生动的细节描写
  • 保持历史事实的准确性
  • 控制篇幅在 200-500 字

4.5.2 提示词模板库

文件：src/generation/prompts.py

提供 5 种写作风格模板：

风格 常量名 特点 适用场景
standard STANDARD 平衡的文学性描述 通用
nostalgic NOSTALGIC 温暖怀旧笔调，强调感官描写 回忆录主体
narrative NARRATIVE 个人命运与时代洪流交织 传记
informative INFORMATIVE 简洁信息，100-200字 注释/脚注
conversational CONVERSATIONAL 像长辈给晚辈讲故事 口述史

系统提示词角色（3 种）：

角色 Key 特点
默认 default 回忆录作家 + 历史学者
历史学者 historian 严谨的史实核查 + 学术表达
小说家 novelist 营造时代氛围 + 感官体验

使用示例：

from src.generation import PromptTemplates

# 获取指定风格的模板
template = PromptTemplates.get_template("nostalgic")

# 列出所有风格
styles = PromptTemplates.list_styles()
# {"standard": "标准风格 - 平衡的文学性描述", ...}

4.6 评估模块 (evaluation)

4.6.1 评估器

文件：src/evaluation/evaluator.py

Evaluator 支持两种评估模式：

模式 说明
LLM 评估 使用 LLM 从准确性、相关性、文学性三个维度打分 (0-10)
规则评估 不依赖 LLM，基于文本特征自动计算分数

评估维度：

维度 权重 评估内容
事实准确性 (Accuracy) 40% 实体引用、时间一致性、地点一致性
相关性 (Relevance) 30% 关键词重叠、主题匹配
文学性 (Literary) 30% 长度、段落结构、过渡词、描述丰富度

BatchEvaluator 支持批量对比评估多个 LLM 的输出，并生成 Markdown 格式的对比报告。

4.6.2 评估指标

文件：src/evaluation/metrics.py

提供 8 项细粒度自动化指标：

类别 指标 说明
准确性 entity_coverage 检索实体在生成文本中的覆盖率
准确性 time_consistency 年份是否与回忆录一致
相关性 keyword_overlap 关键词匹配率
相关性 semantic_similarity 基于字符频率的余弦相似度
文学性 length_score 长度是否在 200-500 字最佳范围
文学性 paragraph_structure 段落数是否在 1-3 个
文学性 transition_usage 过渡词（”那时”、”当时”等）使用情况
文学性 descriptive_richness 感官词、比喻、情感词使用丰富度

使用示例：

from src.evaluation.metrics import calculate_all_metrics, aggregate_scores

metrics = calculate_all_metrics(
    memoir_text="1988年夏天，我来到深圳...",
    generated_text="那是一个激情燃烧的年代...",
    reference_entities=["深圳", "经济特区"],
    reference_year="1988",
)

score = aggregate_scores(metrics)  # 综合分数 0-10

7. 启动与运行

7.1 快速启动

# 方式一：一键启动脚本（推荐）
bash /data/jiabao/RAG/GraphRAG/start.sh

# 方式二：手动启动
conda activate RAG
cd /data/jiabao/RAG/GraphRAG
python run_web.py gradio --host 0.0.0.0 --port 8000

7.2 启动模式

命令 说明
python run_web.py gradio 启动 Gradio 界面 (默认)
python run_web.py api 启动 FastAPI 服务
python run_web.py both 同时启动两者 (Gradio:8000, API:8001)
python run_web.py gradio --port 7860 指定端口
python run_web.py gradio --share 生成公网临时链接

7.3 使用步骤

第一步：准备数据

将历史事件数据放入 data/input/ 目录（支持 TXT / JSON / CSV）。

第二步：构建索引

在 Web 界面的 “⚙️ 索引管理” 标签页点击 “构建索引”，或通过命令行：

python -c "from src.indexing import GraphBuilder; GraphBuilder(llm_provider='ollama').build_index_sync()"

第三步：生成历史背景

  1. 打开浏览器访问 http://localhost:8000
  2. 在 “📝 生成历史背景” 标签页输入回忆录片段
  3. 选择 LLM 模型（默认 ollama/qwen3:32b）和写作风格
  4. 点击 “🚀 生成历史背景”

7.4 远程访问

由于服务器通过跳板机连接，需在本地终端执行 SSH 端口转发：

ssh -L 8000:localhost:8000 -J 跳板机地址 服务器地址

然后在本地浏览器打开 http://localhost:8000。

本次开发新增了完整的本地 Ollama 模型支持链路，使整个项目默认使用本地部署的 Qwen3:32b，不再依赖任何云端 API。

8.1 改动清单

文件 改动内容

src/llm/__init__.py 导出 OllamaAdapter

env.example / .env 新增 Ollama 配置示例
start.sh 新建一键启动脚本

8.2 OllamaAdapter 技术细节

class OllamaAdapter(LLMAdapter):
    # 通过 LiteLLM 的 ollama_chat/ 前缀调用本地模型
    # 不需要真实 API 密钥（传入占位符 "ollama"）
    # 覆写 chat() 和 chat_sync()，确保 api_base 正确设置

    def _get_litellm_model_name(self):
        return f"ollama_chat/{self._get_model()}"
        # 例如: "ollama_chat/qwen3:32b"

8.3 GraphRAG 索引的 Ollama 适配

GraphRAG 本身不直接支持 Ollama，我们通过其 OpenAI 兼容接口 实现对接：

# 自动生成的 settings.yaml 中的关键配置
models:
  default_chat_model:
    model_provider: openai           # 使用 OpenAI 兼容协议
    api_base: http://localhost:11434/v1  # 指向 Ollama 的 /v1 端点
    model: qwen3:32b
    concurrent_requests: 1           # 降低并发避免 OOM
    async_mode: threaded
